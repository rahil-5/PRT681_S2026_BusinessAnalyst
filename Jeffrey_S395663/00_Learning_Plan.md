# Business Analyst — 5-Week Learning Plan

**Student:** Jeffrey Chua Jia Hao (S395663)  
**Role:** Business Analyst  
**Goal:** Build practical BA skills that match common job requirements, then practise them on one running example.

> **Running example used in all five weeks:** overdue invoice collections.  
> A Business Analyst helps Finance see which customers are overdue, how money is collected, and whether a new tracker actually solves the problem.

---

## Skills this plan covers

| Category | Common requirements |
| --- | --- |
| Requirements analysis | Gather, analyse and document business and functional requirements |
| Stakeholder management | Communicate with business, technical and project stakeholders |
| Workshop facilitation | Conduct interviews, workshops and stakeholder meetings |
| Documentation | Produce user stories, functional specifications and business requirements |
| Process analysis | Analyse current processes and identify improvements |
| Communication | Translate technical information into clear business language |
| Risk management | Identify risks, assumptions, issues and dependencies (RAID) |
| Solution delivery | Work with technical teams to ensure solutions meet business needs |
| Personal skills | Work independently, manage priorities and solve complex problems |

| SQL | Query and analyse data | SQL tutorials |

---

## Weekly activities

| Week | Focus | Learning activities | Main deliverable |
| --- | --- | --- | --- |
| Week 1 | Foundations and Jira | Learn the BA role, core tools, and practise creating user stories in Jira | Skills table, tool notes, sample user stories |
| Week 2 | Process mapping | Learn Microsoft Visio and create a simple As-Is and To-Be process map | As-Is / To-Be collections process |
| Week 3 | Data and reporting | Learn basic SQL queries and create a simple Power BI report | Overdue-invoice query + collections dashboard notes |
| Week 4 | Requirements | Turn the process into a BRD, user stories, acceptance criteria and a simple wireframe | Mini BRD + Jira-ready stories |
| Week 5 | UAT and handover | Stakeholder map, RAID log, traceability, UAT scripts and release handover | RTM, UAT plan, handover checklist |

**Study approach:** breadth over depth. Each week should produce something a team could actually use, not only theory.

---

## How the weeks connect

```
Business problem (overdue collections)
        ↓
Week 1  Role, tools, first user stories in Jira
        ↓
Week 2  As-Is process → To-Be process (Visio)
        ↓
Week 3  Evidence from SQL + Power BI dashboard
        ↓
Week 4  BRD, stories, Gherkin, wireframe, Confluence
        ↓
Week 5  Stakeholders, UAT, traceability, sign-off, handover
```

Every documented requirement should be able to answer: **who needs it, why it matters, how we know it is done, and who signs it off.**
